# Резервные копии базы данных Simple CRM

## Как запустить

Откройте терминал в папке проекта и выполните:

```bash
SUPABASE_DB_URL="postgresql://postgres:[ВАШ_ПАРОЛЬ]@db.tqtskuntdahnucuprbhs.supabase.co:5432/postgres" ./scripts/backup-db.sh
```

Или без переменной — скрипт спросит URL интерактивно:

```bash
./scripts/backup-db.sh
```

**Где взять URL:** Supabase Dashboard → ваш проект → Project Settings → Database → вкладка «Connection string» → URI.

---

## Что нужно для работы скрипта

Должны быть установлены клиентские инструменты PostgreSQL (`pg_dump`).

```bash
brew install libpq
```

После установки добавьте в PATH (один раз):

```bash
echo 'export PATH="/opt/homebrew/opt/libpq/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc
```

## Где лежат копии

В этой папке — `backups/`. Файлы называются по дате и времени:

```
backups/crm-2025-10-17_14-30.sql.gz
```

Хранится не более 8 последних копий — старые удаляются автоматически.

**Важно:** файлы копий содержат персональные данные клиентов и сотрудников. Они не попадают в git (прописано в `.gitignore`). Не отправляйте их никуда без необходимости.

## Как проверить копию

Откройте архив и убедитесь, что данные есть:

```bash
# Посмотреть список таблиц (macOS: gunzip -c; Linux: zcat)
gunzip -c backups/crm-ДАТА.sql.gz | grep 'INSERT INTO "public"' | cut -d'"' -f4 | sort -u

# Найти данные клиентов
gunzip -c backups/crm-ДАТА.sql.gz | grep 'INSERT INTO "public"."clients"'

# Посчитать строки клиентов в архиве
gunzip -c backups/crm-ДАТА.sql.gz | grep -c '^\t(' | head -1
```

Если видите строки — копия рабочая.

## Как восстановить

> **Предупреждение:** восстановление в существующую базу перезапишет данные. Выполняйте только после консультации и только если точно понимаете, что делаете.

Общая схема восстановления:

1. Создайте новый пустой проект Supabase (или убедитесь, что текущий готов к полному сбросу).
2. Распакуйте архив:
   ```bash
   gunzip -k backups/crm-ДАТА.sql.gz   # создаст .sql файл рядом
   # или через zcat:
   zcat backups/crm-ДАТА.sql.gz > /tmp/restore.sql
   ```
3. Выполните схему, затем данные:
   ```bash
   psql "$SUPABASE_DB_URL" -f /tmp/restore.sql
   ```
4. Проверьте, что данные появились в Supabase Dashboard → Table Editor.

## Что НЕ входит в копию

Дамп базы данных **не включает файлы** из Supabase Storage (фото клиентов, скрины переписок, памятки, регламенты из папки «Кабинет»).

Чтобы сохранить файлы вручную:

1. Откройте Supabase Dashboard → Storage.
2. Зайдите в каждый bucket (например, `client-files`, `documents`).
3. Выберите все файлы и скачайте их на компьютер.

При необходимости можно написать отдельный скрипт для автоматического скачивания файлов из Storage.

## Как часто делать копии

- **Раз в неделю** — регулярная резервная копия.
- **Перед любыми крупными правками** — изменением структуры таблиц, массовым обновлением данных, обновлением приложения.

Удобно поставить напоминание в календарь — например, каждое воскресенье вечером.
